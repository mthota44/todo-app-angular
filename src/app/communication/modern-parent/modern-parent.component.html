Angular Signals Explained (v16/v17+)

Signals are Angular's new reactive primitive. They represent a value that can change over time and automatically notify anything that depends on it (like templates or computed values) when it changes.

1. The Basics: Writable Signals

A WritableSignal is created using signal(initialValue). You read it by calling it like a function: mySignal(). You can change it using .set() or .update().

Current Value: {{ basicSignal() }}

2. Computed Signals (Derived State)

Created using computed(() => ...). It automatically tracks any signals you read inside it. It only recalculates when its dependencies change, and its value is cached (memoized). It is Read-Only.

Computed Value: {{ computedSignal() }}

3. Effects (Side Effects)

An effect(() => ...) runs immediately at least once, and then runs again anytime a tracked signal inside it changes. Useful for things like logging, local storage, or API calls, but NOT for setting other signals (by default).

4. Advanced / Edge Cases: untracked()

Sometimes you need to read a signal inside an effect or computed WITHOUT triggering a re-run when that specific signal changes. You use untracked().

Notice that clicking this button does NOT trigger the effect below, because we read it using untracked(). The effect only runs when you click the Basic Signal buttons above!

5. Advanced / Edge Cases: Custom Equality Function

By default, signals check if the value changed using === (referential equality). For objects, you can provide a custom equality function to prevent unnecessary updates if the logical data hasn't changed.

User Data (ID determines equality): {{ userSignal() | json }}

Clicking "Same ID" changes the name in memory, but because our custom equality function says "if ID is same, it's equal", Angular does not trigger a re-render!
